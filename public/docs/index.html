Nexus AI is a RAG knowledge assistant that extracts selectable PDF text, stores overlapping chunks in Neon Postgres, retrieves relevant context, and uses a server-side Groq model to support source-aware answers.

What is Nexus AI?

Nexus AI combines document ingestion, chunk persistence, hybrid retrieval, and language-model generation so users can ask questions about indexed PDFs and inspect the context selected for responses.

PDF → text extraction → overlapping chunks → Neon Postgres → embeddings → full-text + vector search → RRF → Groq → answer

How does document question answering work?

The current upload path accepts selectable-text PDFs up to 25 MB. The backend parses page text, normalizes it, creates overlapping chunks, generates a 384-dimension embedding for each chunk with a local MiniLM model, and writes the document plus chunks in a Neon Postgres transaction. Scanned PDFs without selectable text require OCR and are rejected.

What is hybrid retrieval?

Hybrid retrieval combines exact keyword signals with semantic similarity so technical identifiers and related language can both be discoverable. Each question runs two searches in parallel: Postgres full-text search (ranked with ts_rank_cd) and pgvector cosine similarity over chunk embeddings. The two ranked lists are merged with Reciprocal Rank Fusion (k = 60) and the top six chunks are sent to the Groq model as context.

Answer quality depends on the source document, chunking, retrieval results, selected model, and available context. Nexus AI does not guarantee perfect accuracy.

Which endpoints are available?

GET /api/auth/me checks the session. POST /api/auth/signup creates an account. POST /api/auth/login starts an HttpOnly session. Authenticated clients can use GET /api/documents, POST /api/documents/upload, and POST /api/chat.

How does Nexus AI handle access?

Accounts are stored in Neon Postgres. Passwords are salted and hashed with Node’s scrypt implementation; plaintext passwords are never persisted. Session tokens are stored as SHA-256 hashes and delivered through HttpOnly cookies. Groq and Neon credentials remain server-side.

Current limitations

OCR for scanned PDFs, email ownership verification, password reset, per-user document isolation, a measured retrieval evaluation, and a cross-encoder reranker are not included in the current implementation.
